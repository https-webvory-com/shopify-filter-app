# Single-term search product pinning

Creating or editing a targeted search pin now uses one search-term field. Changing it replaces the previous term on the same rule, retains pinned products/order and refreshes the matching product picker. The save action rejects empty, malformed and multiple-term targets; it does not enable disabled rules or alter instant/page scope. Existing all-search rules remain supported. Legacy multi-term rules are not migrated automatically: the editor shows their saved terms and requires an explicit single-term choice before saving. Existing matching/import data remains compatible until that choice is saved. No database migration or theme-extension update is required for this editor change.

Run `node tests/search-pinning/run-headless.mjs` for the actual React creation/editor and action checks in an isolated Chrome session against an in-memory catalog. This includes matching-product pagination, pin order/group dragging, creation, replacement/reload, blank and rapid term changes, and legacy-rule preservation. `tests/search/single-term-pinning.test.mjs` verifies server validation, replacement and runtime matching on both search surfaces. Reports are under ignored `scratch/single-term-pinning-*`; no live saved rules are changed by these tests.
