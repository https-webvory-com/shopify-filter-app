# Single-term search product pinning

Creating or editing a targeted search pin now uses one search-term field. Changing it replaces the previous term on the same rule, retains pinned products/order and refreshes the matching product picker. The save action rejects empty, malformed and multiple-term targets; it does not enable disabled rules or alter instant/page scope. Existing all-search rules remain supported. Legacy multi-term rules are not migrated automatically: the editor shows their saved terms and requires an explicit single-term choice before saving. Existing matching/import data remains compatible until that choice is saved. No database migration or theme-extension update is required for this editor change.

Run `node tests/search-pinning/run-headless.mjs` for the actual React creation/editor and action checks in an isolated Chrome session against an in-memory catalog. This includes matching-product pagination, pin order/group dragging, creation, replacement/reload, blank and rapid term changes, and legacy-rule preservation. `tests/search/single-term-pinning.test.mjs` verifies server validation, replacement and runtime matching on both search surfaces. Reports are under ignored `scratch/single-term-pinning-*`; no live saved rules are changed by these tests.


## Imported rule order

Search and collection pinning imports now retain CSV record order in the default admin list, including files split across parallel batches. Each upload stores one group and the original record position in the nullable `PinnedProductRule.importOrder` column. Skipped rows leave gaps; surviving rules retain their relative order. Re-importing updates this ordering on matching rules without changing their real creation dates. Default exports follow the same order. Newest first and Oldest first remain explicit date sorts; manual rules without import metadata retain date-based placement. Storefront rule precedence and the products/order inside a rule are unchanged.

Deploy the backend/admin build and additive Prisma schema together; the normal deployment schema push creates the nullable column. No theme-extension publication is required. Existing imports do not contain the original CSV positions: re-import the source CSV after deployment to restore their order, then select Default order. The fix preserves the order present in the exported file; it cannot reconstruct an order absent from that file. Existing name-based import matching still applies.

`tests/search/pin-import-order.test.mjs` covers parallel batches, 151 rules per type, reversed re-imports, unchanged creation dates and product order, skipped/invalid positions, filters, same-millisecond uploads, manual rules, and date-sort overrides. The actual CSV modal browser fixture in `tests/csv-import` checks source positions across 151 rows and skipped entries for both pinning types. CSV export tests cover rule/product-order round trips.
